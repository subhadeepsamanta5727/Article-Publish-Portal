SEO ARTICLE PUBLISHING PORTAL - PROJECT DOCUMENTATION

1. PROJECT OVERVIEW

SEO is a MERN based article publishing portal. Users can register, choose publication
packages, pay online, write article content, submit articles for review, view payment
history, and download PDFs. Admin users can manage packages, review articles, update
article status, see dashboard statistics, and download article/payment PDFs.

The project has two main parts:

Backend:
SEO-ArticlePublishPortal/Backend

Frontend:
SEO-ArticlePublishPortal/seo-app

7. BACKEND WORKFLOW

Registration and login:
User registers or logs in through the auth APIs. Passwords are hashed with bcryptjs.
JWT tokens are used for protected routes.

Article creation:
User selects publication packages and article quantity. The backend creates article
records for the selected package items. Admin users are not allowed to create new
articles from the frontend flow.

Payment:
The frontend sends selected article IDs to create a Razorpay order. The backend
calculates the total amount from saved article package prices. After successful
Razorpay verification, the payment becomes paid and the related articles move to
writing status.

Writing:
After payment, the user can open the article workspace and add title, keywords,
abstract, image, resource link, and content.

Submission:
When the user submits the article, the status changes to submitted.

Admin review:
Admin can change article status to Under Processing, Published, or Failed.
Internally these statuses are saved as under_review, accepted, or rejected.

PDF generation:
PDFs are generated using PDFKit. Article PDFs and payment PDFs are available for
download.

14. ARTICLE LIFECYCLE

Article flow:

draft
payment_pending
writing
submitted
under_review
accepted or rejected

Meaning:
- draft: Article created but not ready
- payment_pending: Payment is not completed
- writing: Payment completed and user can write article
- submitted: User submitted article to admin
- under_review: Admin marked article as under processing
- accepted: Admin published/accepted article
- rejected: Admin failed/rejected article


15. PAYMENT FLOW

Step 1:
User selects package and quantity.

Step 2:
Backend creates article records.

Step 3:
Frontend opens checkout page.

Step 4:
Frontend requests Razorpay order from backend.

Step 5:
Backend calculates total amount from article packagePrice values.

Step 6:
User completes Razorpay payment.

Step 7:
Frontend sends Razorpay verification details to backend.

Step 8:
Backend verifies payment signature.

Step 9:
Payment becomes paid.

Step 10:
Related articles become writing status.

17. BRANDING

Visible project name:
SEO

The short-lived access token uses an internal localStorage key:
- seo_access_token

Refresh tokens are stored in an HttpOnly, Secure, SameSite cookie and are never
returned to or stored by the frontend. Refresh requests require the CSRF token
header and rotate the refresh cookie. Set VITE_API_URL in the frontend build
environment to the production API base URL; localhost is only the development fallback.

These can stay as internal keys unless a full internal rename is required.


18. IMPORTANT NOTES

Use npm.cmd in PowerShell if npm.ps1 is blocked.

Admin accounts require role admin in the database.

Razorpay requires valid key ID and secret.

Image upload currently stores image data in the article model. For production,
external file storage is recommended.

Package prices are preserved on articles after creation so old article payments
are not changed by future package price edits.

Only authenticated users can access article, payment, and PDF routes.

Only admins can access admin package, admin article review, and admin dashboard APIs.
